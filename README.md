# UE5 资产合规管线（早期版本 · 源码未保留）

> ⚠️ **先说清楚**：这个仓库现在只有 `LICENSE` 和 `.gitignore`，**没有可运行代码**。
> 不是忘了上传——最早那版没有做版本管理，源码在重装系统时丢了，只剩打包好的 EXE 和插件（在本地磁盘上）。

## 这条线是干什么的

解压 zip → 导入 UE → 命名与贴图设置校验 → 自动修复 → 出报告。

目标很朴素：**美术把资产包丢进来，剩下的不用管。** 当时最想解决的是"310 个资产里有 15 个名字不规范，靠人一个个看"这件事。

## 留下的可核实数据

| 场景 | 结果 | 出处 |
| --- | --- | --- |
| 149–150 个资产的规则校验 | 3 秒内完成 | 早期测试日志 |
| 310 个资产的规则校验 | 发现 15 处命名问题，自动修复 15 处 | 终端 + UE 输出日志 |

> 完整记录（含"哪些无法复现"的说明）见 [docs/历史数据.md](docs/历史数据.md)。

## 它后来去哪了

2026.10 重写为 **[UE5-AI-Asset-Pipeline](https://github.com/WOBO538/UE5-AI-Asset-Pipeline)**（V3）：四层解耦、AI 语义层、内容寻址缓存，最大实测 310 个资产、外部流转 0.21 秒。

版本关系：作品集与简历把这条线统一表述为 **V1 → V3**——同一个流程的几个阶段，不是一个项目改名了三次。

## 为什么还留着这个空仓库

1. 它是这条线的起点。删掉的话，"V1 → V3"里的 V1 就没有出处了。
2. 它记录了一个真实的教训：**没有版本管理，项目最终只剩下一个 exe。**

## 一句诚实声明

如果判断一个项目必须**以源码为准**——那这个仓库不该被算作作品，请直接看 V3。

把它留在这里的原因，是"丢掉过一次源码"这件事本身值得留在履历里，而不是拿一个空仓库凑数。
